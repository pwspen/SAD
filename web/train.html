Site countThe only settings that decide how many sites the run uses. The count goes from start sites at iteration 0 to end sites by reach end by, on the chosen curve, then holds while the rest of the run refines. Start < end grows by splitting the cells a second site would explain best; start > end prunes, merging the cheapest neighbouring pairs into one site (the pixel-weighted average of both); start = end is a fixed count. Each site costs 128 bits: bpp = sites × 128 / (width × height).

sites at iteration 0

Placed at iteration 0 by the default edge-based init (1 works). A loaded init sites file sets this to its own count.

sites once the schedule is done

Where the count ends up. Below start sites the run prunes: each step merges the cheapest neighbouring pairs (the least squared error added with the merged cell at its mean color), each site in at most one merge per step. On Kodak at 256 px, 1600 → 400 beat a fixed 400 (28.8 vs 28.1 dB); on MNIST 128 → 16 was still behind a fixed 16.
The curve from start to end. linear: the same number of sites per step. exponential: the same factor per step, so few sites change early and many late when growing (the other way round when pruning). sawtooth: the exponential curve with teeth on top: each tooth grows above it by amplitude, then merges back down to it. Tuned and checked on held-out images, sawtooth beat the best exponential by about 0.8 dB on MNIST and 0.6 dB on Kodak at 256 px (the presets use it). Teeth shorter than a few steps can't go down: the summary warns when a sawtooth never merges.

fraction of the run (0–1)

The count reaches end sites at this fraction of the iterations (a step merges at most half the sites, so a big sawtooth may take a few more steps to get back down); the rest of the run refines that set (with decay after growth, the LR cools down from here). Slow ramps take many small steps, and LR decay compounds per growth step.

teeth before the count reaches the end

Frequency: how many grow-then-merge cycles fit between iteration 0 and reach end by.

peak above the curve, as a fraction of it

Each tooth peaks at (1 + this) × the exponential curve's count at that point, e.g. 0.5 = 50% more sites, then merges back down to the curve.

time growing per unit of time merging, within a tooth

3 = each tooth spends 3/4 of its time growing up to the peak and 1/4 merging back down.

iterations between count steps

Time for each batch to settle before the next is placed. Too short and the next step still sees the old error where the last batch landed. Growth finishes after (number of steps) × this, e.g. 1 → 64 with factor 2 and 25 takes 6 steps, done at iteration 150.

Preset

Saves every field above (and the preset's settings that have no field) in this browser as the defaults preset. Reset goes back to training_config.json and the trainer's built-in defaults.

Input

none
Pixels that aren't pure black count toward the loss and PSNR. Black pixels are ignored by sites, growth and the score.
gradient init
Start from these sites instead of the default placement (sites sampled where the image has edges). Positions are rescaled to the target size and every site's τ is reset. Its site count becomes the starting count: it replaces start sites, which is locked to show it until the file is cleared.

ScheduleEverything that decides when things happen in a run: how long it is, how the learning rate moves, and (in grow mode) when sites are added and when growth stops. The summary below is worked out from these fields as you edit them; after a run it also says when and why growth actually ended.

iterations

Run length. There is no learning-rate warmup: every rate starts at full (in tests a 200-iteration warmup was within ±0.2 dB).
How the learning rate changes over the run. cosine: falls from full to 0 on a cosine over the run. fixed: stays at full. decay after growth: stays at full while sites are being added, then falls to 0 on a cosine by the end of the run, so late sites aren't starved and the finished set still gets a cool-down (with fixed site count it equals cosine). The cool-down matters: without it MNIST lost 1–1.5 dB.

error per bit: 8-bit levels² (summed over R, G, B and pixels)

Only cells whose split would remove more than λ × 128 levels² of error (a site costs 128 bits) are split; a step adds fewer sites if fewer qualify, and growth ends early once none do. Example: λ = 400 → 51,200 levels², e.g. 100 pixels each off by about 13 levels in all three channels. Higher λ stops sooner. 0 = never stop early (any site that helps at all qualifies). The log says which limit ended growth.
learned depth: the peak of the image's smoothed color histogram (MNIST's black) becomes a flat layer behind every site, a site with a constant logit β that every pixel blends. A site wins wherever its own logit beats β, and the layer's color shows everywhere else, so no sites are spent drawing it. β is learned, starting from how common that color is: on MNIST the layer comes forward and takes the background (+3 dB at 32 sites); on Kodak it stays mostly behind (−0.1 dB). It never splits or merges, counts as one of the sites, and is an ordinary site in the saved file.

Logging

iterations between refreshes

How often training pauses to read back the render and update PSNR, gradient stats, the plots, the preview images and the site overlay. Smaller = finer curves and a livelier view, slower runs. Doesn't change what is learned.

CandidatesEach pixel blends only its 8 best-scoring sites, kept in a per-pixel candidate list. These settings control how the lists are searched as sites move: better search means more accurate renders and gradients, at more cost per iteration. "Pass" below = one search sweep over every candidate pixel.

iterations between list refreshes

1 = refresh every iteration (most accurate); larger is faster, but lists go stale as sites move.

passes per refresh

Each pass merges in neighbouring pixels' lists; the first passes of a run reach far (jump flooding), later ones only adjacent pixels.

image pixels per candidate cell, per side (integer)

2 = one shared list per 2×2 pixels. Faster and lighter, but sites smaller than a cell can be missed. 1 = one list per pixel.

candidate cells per 1024 cells of grid width

Distance of the radius probes below; scales with the grid, e.g. 64 → 48 cells on a 768-wide grid.

probes per pixel per pass

Also merge the lists of this many cells in random directions at the distance above, so large sites reach far pixels. 0 = off.

random sites per pixel per pass

Also try this many sites picked at random from all sites: a global safety net so no site stays undiscovered.

Color

What a site's three color numbers mean while optimizing. RGB: red, green, blue on 0–1 (1 = 255 levels). Log intensity + chroma: mean natural-log brightness, then log(R/G) and log(B/G), so a pure brightness change moves one number. Blending, the loss and saved files are always RGB.

Loss

What training minimizes, per color channel. L2 (squared error): each site's color is the mean of the pixels it covers, so a cell straddling black and white goes grey. L1 (absolute error): the median instead, so a mostly-white cell goes white and the boundaries are pushed onto the edges. PSNR, growth and λ use squared error either way, so L1 runs score a little lower.

α (0 = off)

Pulls harder on error that stays put. Every pixel keeps a running average of its signed error; where the error keeps the same sign iteration after iteration, the average stays large, and where it flips (noise, a boundary sweeping past) it cancels. Each pixel's loss is multiplied by (1 + α · its average error² over the image mean, capped) / (1 + α), so the mean weight stays near 1 and pixels with persistent error count up to (1 + α · cap) / (1 + α) times more. Costs one extra read and write per pixel per iteration.

β per iteration (memory ≈ 1 / (1 − β) iterations)

How long the running average remembers: 0.95 ≈ the last 20 iterations. Longer memory picks out only error that has stayed for a long time, but reacts later once it's fixed.

× the mean

Largest average error that counts, as a multiple of the image mean. Keeps error that no site can remove (fine texture) from taking the whole loss.
Growth weighs each pixel by the same weight when picking cells to split and placing the new site, so splits go where the error has persisted. λ then compares against weighted error. Needs persist weight > 0.

Learning ratesAdam step sizes. Adam moves a parameter by about its rate per iteration, in that parameter's units, so each unit below is "per iteration". Rate used = base below × LR mult × the LR schedule (set under Schedule), e.g. pos 0.025 × 3 = up to 0.075 px per iteration.

× (multiplier on every base rate)

Scales every base rate below: the quickest single knob for faster but riskier (higher) or calmer (lower) training.

pixels per iteration

Site position.

natural-log units of τ per iteration

τ is edge sharpness, measured per image long side: a site's edge blends over roughly (long side ÷ τ) px. E.g. log τ = 5 (τ ≈ 148) on a 768 px image ≈ 5 px edges; a step of 0.03 changes τ by about 3%.

pixels per iteration

Radius is an offset in pixels that lets a site claim more (or less) area than its neighbours. Only differences between neighbouring sites matter.

color-space units per iteration

RGB: 0–1 per channel, so 0.01 ≈ 2.5 levels. Log intensity + chroma: natural-log units, so 0.01 ≈ a 1% change.

unit-vector components per iteration (≈ radians for small turns)

Direction of the site's stretch. Frozen for the first 50 iterations.

natural log of the aspect ratio per iteration

Anisotropy: 0 = round, ±1 ≈ 2.7:1, clamped to ±2 ≈ 7.4:1. Frozen for the first 50 iterations.
