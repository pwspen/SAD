Sites & logging

sites (128 bits each)

Growth off: the exact count for the whole run. Growth on: the maximum. Bits per pixel = sites × 128 / (width × height).

iterations between refreshes

How often training pauses to read back the render and update PSNR, gradient stats, the plots, the preview images and the site overlay. Smaller = finer curves and a livelier view, slower runs. Doesn't change what is learned.

Site growthInstead of a fixed count, start small and add a site only where it pays for its bits on the rate–distortion curve: where it would remove more error than λ × 128 bits is worth. Growth runs coarse to fine and stops by itself, so λ picks the operating point (bpp vs PSNR) and the site count follows. Sites are never removed.

squared error per bit: 8-bit levels² (summed over R, G, B and pixels) per bit

One site costs 128 bits, so a new site must remove more than λ × 128 levels² of error. Example: λ = 400 → 51,200 levels², e.g. 100 pixels each off by about 13 levels in all three channels. Higher λ → fewer sites, lower bpp, lower PSNR. On Kodak, 1600 gave about 1–4k sites, 400 about 4–9k, 100 about 9–30k. 0 = growth off.

sites

Count at iteration 0, placed by the default edge-based init. Growth only adds, so this is also the minimum. 256 beat 16 in tests (tiny starts waste the first checks).

iterations between growth checks

Each check adds at most one site per site-spacing cell, so the count at most about doubles per check. Longer gaps let the fit settle and end with fewer sites; 10 gave the best quality per site.

iteration number (blank = 60% of the run)

No sites are added from this iteration on; the rest of the run refines the sites it has. Growth usually stops on its own well before.

multiple of the site spacing (unitless); σ in px = this × √(mask pixels / sites)

While growing, train against the image blurred with that Gaussian σ (e.g. 0.375 × 20 px spacing = 7.5 px). The blur shrinks as sites are added and stops at end iter. 0 = off (recommended): it cost 0.5–2 dB in tests, since sites draw edges far finer than their spacing.

CandidatesEach pixel blends only its 8 best-scoring sites, kept in a per-pixel candidate list. These settings control how the lists are searched as sites move: better search means more accurate renders and gradients, at more cost per iteration. "Pass" below = one search sweep over every candidate pixel.

iterations between list refreshes

1 = refresh every iteration (most accurate); larger is faster, but lists go stale as sites move.

passes per refresh

Each pass merges in neighbouring pixels' lists; the first passes of a run reach far (jump flooding), later ones only adjacent pixels.

image pixels per candidate cell, per side (integer)

2 = one shared list per 2×2 pixels. Faster and lighter, but sites smaller than a cell can be missed. 1 = one list per pixel.

candidate cells per 1024 cells of grid width

Distance of the radius probes below; scales with the grid, e.g. 64 → 48 cells on a 768-wide grid.

probes per pixel per pass

Also merge the lists of this many cells in random directions at the distance above, so large sites reach far pixels. 0 = off.

random sites per pixel per pass

Also try this many sites picked at random from all sites: a global safety net so no site stays undiscovered.

± positions in the Hilbert-sorted site list

Sites are sorted along a Hilbert curve, which keeps nearby sites close in the list; Hilbert probes pick within this many places either side of the pixel's best site. 0 = off.

sites per pixel per pass

How many of those Hilbert neighbours each pixel tries. 0 = off.

Color

choice; sets the units of the color numbers

What a site's three color numbers mean while optimizing. RGB: red, green, blue on 0–1 (1 = 255 levels). Log intensity + chroma: mean natural-log brightness, then log(R/G) and log(B/G), so a pure brightness change moves one number. Blending, the loss and saved files are always RGB.

Learning ratesAdam step sizes. Adam moves a parameter by about its rate per iteration, in that parameter's units, so each unit below is "per iteration". Rate used = base below × LR mult × the warmup/decay schedule (e.g. pos 0.025 × 3 = up to 0.075 px per iteration).

iterations

Every learning rate ramps linearly from 0 to full over this many iterations. Run length = warmup + decay.

iterations

After warmup, the learning rates fall to 0 on a cosine curve over this many iterations.

unitless multiplier

Scales every base rate below: the quickest single knob for faster but riskier (higher) or calmer (lower) training.

pixels per iteration

Site position.

natural-log units of τ per iteration

τ is edge sharpness, measured per image long side: a site's edge blends over roughly (long side ÷ τ) px. E.g. log τ = 5 (τ ≈ 148) on a 768 px image ≈ 5 px edges; a step of 0.03 changes τ by about 3%.

pixels per iteration

Radius is an offset in pixels that lets a site claim more (or less) area than its neighbours. Only differences between neighbouring sites matter.

color-space units per iteration

RGB: 0–1 per channel, so 0.01 ≈ 2.5 levels. Log intensity + chroma: natural-log units, so 0.01 ≈ a 1% change.

unit-vector components per iteration (≈ radians for small turns)

Direction of the site's stretch. Frozen for the first 50 iterations.

natural log of the aspect ratio per iteration

Anisotropy: 0 = round, ±1 ≈ 2.7:1, clamped to ±2 ≈ 7.4:1. Frozen for the first 50 iterations.
